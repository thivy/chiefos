# Conventions

Shared rules for every step of every ChiefOS skill. No other file restates them. A step may add a stricter rule, but must never contradict one here.

## Voice and Formatting

Applies to all user-facing output: briefings, summaries, todos, memory notes, and drafted messages.

- Write in Australian English.
- Do not use em dashes. Use commas, semicolons, colons, or separate sentences.
- Keep language concise, neutral, and action-oriented for a busy professional reader. Avoid assistant narration.
- Format a date and time as `Mon 12 Apr, 9:30am` in the local time zone.
- Use the current local date and time for every calculation, greeting, and timestamp.

## Evidence

- Never invent a person, recipient, link, fact, commitment, date, deadline, decision, owner, attachment, or signature. Omit the item instead.
- Use only evidence present in the item, its linked context, the calendar, the address book, or `memory.md`. Do not infer relationships, importance, deadlines, or business impact from a title, domain, tone, or metadata alone.
- When evidence conflicts, state the conflict and recommend verification. When it is ambiguous, take the lower defensible reading.

## Working Files

- Replace each working file in place every run. Never create timestamped, backup, or history copies.
- Never store passwords, keys, tokens, secrets, or sensitive personal data in a working file.

## Reporting

- Verify a step's postconditions before reporting it complete. Never report success, delivery, or completion you have not confirmed.
- Never expose triage scores, priority bands, or classification logic in user-facing output.
